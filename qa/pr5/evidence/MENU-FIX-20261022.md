# RightLaw desktop dropdown dismissal fix

22 October 2026. Existing PR #5 draft branch only.

Problem: the CSS group-focus-within rule kept a dropdown visible after a mouse click left focus on its link, even after the pointer moved outside the menu.

Correction: desktop dropdown visibility now uses explicit state. Mouse enter opens it; leaving the complete trigger/dropdown area closes it regardless of retained mouse focus. Keyboard-visible focus still opens it; Escape, focus leaving the menu, or selecting a link closes it. Expansion state is exposed with aria-expanded/aria-controls. Native mobile details menus are preserved.

Validation on a local Next.js production build, Chromium 153:

- Production build passed.
- All six desktop dropdowns at 1365px and 1024px: hover opens, moving into dropdown keeps it open, leaving the menu closes it without any outside click.
- Clicking a top-level menu link, navigating and moving the mouse away leaves no hanging dropdown at both desktop widths.
- Keyboard focus opens; Escape closes at both desktop widths.
- Mobile 390px/360px: menu opens on tap, submenu link selection closes navigation; no horizontal page overflow.

Hosted-preview verification remains separate from local testing. Production/main were not modified; no merge or publish was requested.
